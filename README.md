# MakTerm

Android-терминал (форк ReTerminal, лицензия MIT — файл LICENSE сохранён).

## Что нового в 1.7.0
- **Ядро хостинга процессов переписано на Rust.** Kotlin/Compose остаётся интерфейсом, а жизненным циклом фоновых процессов управляет нативная библиотека `libmakterm_core.so` через JNI.
- Rust запускает процесс, читает stdout/stderr, хранит ограниченный лог, останавливает процесс по SIGTERM/SIGKILL и делает автоперезапуск до 5 раз. Kotlin передаёт готовую команду и окружение (Android shell или proot/chroot `init-host`), поэтому поддержка Linux не потерялась.
- Связь без JNI-колбэков: UI опрашивает компактный JSON-снимок состояния и лог, так что нативные потоки не трогают JVM.
- Добавлены Rust-тесты на запуск, захват вывода и остановку процесса.
- CI собирает `libmakterm_core.so` под `arm64-v8a`, `armeabi-v7a`, `x86_64` и `x86`.
- Версия: `versionCode 18`, `versionName 1.7.0`.

## Что нового в 1.6.0
- **Хостинг любых фоновых процессов.** В настройках появился раздел «Хостинг»: добавьте Telegram-бота, скрипт или любую команду, и MakTerm будет держать её запущенной. Процессы работают в фоне через foreground-сервис с уведомлением, поэтому не умирают при сворачивании приложения.
- Для каждого процесса можно указать название, команду, рабочую папку, порт и режим: внутри Linux (proot/chroot) или в оболочке Android. Есть живой лог, очистка лога и автоперезапуск до 5 раз после сбоя.
- **Дашборд системы**: загрузка CPU, занятая RAM, диск, батарея, время работы и локальный IP — обновляется в реальном времени.
- **Установка инструментов в Linux одной кнопкой**: Python, Node.js, Git, OpenSSH, FFmpeg. Команда сама определяет `apk` (Alpine) или `pacman` (Arch) и показывает прогресс.
- **Резервная копия Linux-системы**: создаёт `tar.gz` с rootfs в `/sdcard/Download`.
- Версия: `versionCode 17`, `versionName 1.6.0`.

## Что нового в 1.5.4
- **Устранён лаг при наборе текста.** Жидкий фон больше не перерисовывается 60 раз в секунду: он обновляется с частотой 20 fps, замирает при открытой клавиатуре и при включённом «Меньше анимации». Параметры шрифта, начертания и палитры терминала теперь применяются только при реальном изменении, а не при каждой перерисовке экрана.
- **Сервер (админ-панель).** В настройках появился раздел «Сервер»: встроенный HTTP-файловый сервер запускается и останавливается одной кнопкой. Можно выбрать порт, общую папку (по умолчанию `/sdcard`), включить пароль (логин `admin`) и открыть ссылку в браузере или скопировать её. Сервер работает по локальной сети, без root и без установки Linux-пакетов.
- Поддержка Range-запросов (докачка файлов), защита от выхода за пределы общей папки, список файлов с размерами и иконками.
- Версия: `versionCode 16`, `versionName 1.5.4`.

## Что было в 1.5.1
- **Исправлен запуск терминала**: proot падал с `CANNOT LINK EXECUTABLE ... library "libtalloc.so" not found`. Теперь в APK поставляются `libloader.so`/`libloader32.so`, а `libtalloc.so` и `libandroid-shmem.so` копируются в `local/lib` перед стартом сессии.
- **Исправлен Arch Linux ARM**: загрузка больше не спотыкается о редирект https → http (HTTP 301/302), архив качается во временный `.part` и проверяется по размеру, а распаковка идёт сразу на экране установки с проверкой результата.
- **Исправлено зависание `rm` при первом запуске**: под proot больше не используется shell-обёртка `rm` (она зависала на `$(...)`); восстанавливается штатный `/bin/rm -> /bin/busybox`, а `resolv.conf` создаётся через `mv`, без вызова `rm`.
- **Исправлена распаковка rootfs**: проверка идёт по реальным файлам (`etc/alpine-release`, `bin/busybox`, `usr/bin/bash`), а не по абсолютной ссылке `/bin/sh`; недокачанный или недорaspакованный rootfs больше не считается установленным и переустанавливается.
- **Новая иконка**: «жидкое стекло» с глифом `>_`, отдельные adaptive-слои (фон, передний план, monochrome).
- В настройках появился пункт **«Переустановить систему»** — удаляет текущий Linux и запускает установку заново (например, чтобы перейти с Alpine на Arch).
- Версия: `versionCode 13`, `versionName 1.5.1`.

## Как получить APK
Репозиторий: https://github.com/dianulublu808-art/MakTerm

- **В приложении**: Настройки → Обновления → Проверить обновления. Приложение само скачает и предложит установить новую версию.
- **Вручную**: GitHub → Releases → последний релиз → `MakTerm-<версия>.apk`.
- **Сборка из исходников**: Actions → Build APK → Run workflow, затем артефакт `MakTerm-APK`.

Имя приложения меняется в `app/build.gradle.kts` (`app_name`), ID пакета — `applicationId`.

## Сборка локально
Требуются JDK 17+ и Android SDK (platform 37, build-tools 37). Модуль `core/proot` использует готовые библиотеки из `src/main/jniLibs`, поэтому NDK/CMake не нужны.
```
./gradlew assembleDebug
```
APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Rust-ядро
`core/rust` — отдельный Cargo-проект (`makterm_core`), который собирается в `libmakterm_core.so`. Исходники лежат в `core/rust/src/lib.rs`, готовые библиотеки — в `core/main/src/main/jniLibs/<abi>/`.

```bash
# Linux/CI: нужен Android NDK и rustup
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/29.0.13846066"
bash core/rust/build-android.sh

# Termux: собирается только arm64, потому что host triple уже Android
ABIS=arm64-v8a CLANG=$(command -v clang) AR=$(command -v llvm-ar) \
  bash core/rust/build-android.sh
```

Тесты супервизора:
```bash
cd core/rust && cargo test --release
```

## Замечания по proot
`libproot.so` запускается из `applicationInfo.nativeLibraryDir`, поэтому рядом должны лежать `libloader.so` (передаётся в `PROOT_LOADER`), а его зависимости (`libtalloc.so`, `libandroid-shmem.so`) — в каталоге из `LD_LIBRARY_PATH` (`local/lib`). Если обновляешь prebuilt-библиотеки proot, не забудь про загрузчик.

## Arch Linux ARM
При выборе Arch архив `ArchLinuxARM-aarch64-latest.tar.gz` скачивается в `files/alpine.tar.gz` и распаковывается в `local/alpine` (путь исторический, на работу не влияет). Для armv7 используется `ArchLinuxARM-armv7-latest.tar.gz`. Нужно ~2–3 ГБ свободного места. Перейти с Alpine на Arch можно через «Настройки → Переустановить систему».
